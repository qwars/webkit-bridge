# ewd-tui

Терминальный интерфейс для управления веб-проектами с `ewd-daemon` — демоном автоматизации браузера WebKitGTK.

## Обзор

`ewd-tui` — терминальный интерфейс, который управляет веб-проектами, собирает их через `esbuild` и запускает через `ewd-daemon` (демон браузера WebKitGTK). Предоставляет управление проектами, отслеживание файлов, авто-сборку, консоль и инспектор сетевых запросов — всё из терминала.

## Ключевые возможности

- **Управление проектами** — создание, удаление и навигация по проектам через список
- **Авто-сборка** — отслеживает файлы и пересобирает через `esbuild` при изменении
- **Интеграция с браузером** — автоматически запускает `ewd-daemon`, создаёт видимую вкладку браузера и загружает URL проекта
- **Инспектор сети** — просмотр сетевых запросов с таймингами, статус-кодами, заголовками и фильтрацией
- **Консоль и логи** — вывод в реальном времени от сборки и логов демона
- **Несколько раскладок** — Emacs, Vim и VSCode (переключение через `Ctrl+K`)
- **Поиск** — фильтрация проектов и сетевых запросов

### Компоненты

| Компонент | Описание |
|---|---|
| `AppState` | Центральное состояние: проекты, экраны, буферы, IPC-клиент, ворчеры |
| `IpcClient` | JSON-RPC 2.0 клиент через Unix сокет (асинхронный, с фоновым ридером) |
| `DaemonManager` | Запускает `ewd-daemon`, управляет жизненным циклом, чистит сокет |
| `ProjectWatcher` | Файловый ворчер на `notify`, запускает сборку при изменении файлов |
| `Keymap` | Три схемы клавиш: Emacs, Vim, VSCode |

## Системные требования

- **ОС:** Linux (тестировалось на Debian 13)
- **Дисплей:** Терминал с поддержкой 256 цветов (true color рекомендуется)
- **Оболочка:** Любая POSIX-совместимая оболочка

### Необходимые зависимости

**Системные пакеты:**

```bash

npm install -g esbuild
```

## Установка

### Сборка из исходников

```bash
git clone <repository-url>
cd webkit-bridge
cargo build --release -p ewd-tui
```

Бинарник будет в `target/release/ewd-tui`.

### Запуск из workspace

```bash
cargo run --release -p ewd-tui
```

## Использование

### Запуск

```bash
ewd-tui
```

При запуске `ewd-tui` выполнит:

1. Проверит наличие `ewd-daemon` и `esbuild` в PATH
2. Создаст директории конфигурации (`~/.config/ewd-tui/`)
3. Запустит `ewd-daemon` как дочерний процесс
4. Подключится к демону через Unix сокет
5. Отобразит список проектов

### Создание проекта

1. Нажмите `n` в списке проектов
2. Заполните форму:
   - **Name** — отображаемое имя проекта
   - **Dir** — имя директории (используется как путь в `~/.config/ewd-tui/projects/`)
   - **URL** — URL, который загрузится во вкладке браузера (например, `http://localhost:3000`)
   - **Entry** — входной файл для esbuild (например, `src/main.js`)
3. Нажмите `Enter` для сохранения, `Esc` для отмены

В `~/.config/ewd-tui/projects/<dir>/` создаётся `config.toml`, а входной файл генерируется, если его нет.

### Вход в проект

1. Навигация по списку: `↑` / `↓`
2. `Enter` — войти в проект
3. Проект собирается через esbuild и открывается во вкладке браузера через `ewd-daemon`

### Переключение вкладок

Внутри проекта переключение между вкладками:

| Клавиша | Вкладка |
|---|---|
| `Shift+C` | Console (вывод сборки) |
| `Shift+N` | Network (запросы) |
| `Shift+R` | Resources |
| `Shift+D` | DOM |
| `Shift+L` | Logs (вывод демона) |

### Сборка и перезапуск

| Клавиша | Действие |
|---|---|
| `F5` / `Ctrl+R` | Собрать и перезапустить проект |
| `Esc` | Выйти из проекта, остановить |

### Удаление проекта

1. Выделите проект в списке
2. Нажмите `d` для начала удаления
3. Подтвердите `y`, отмените `n` или `Esc`

### Поиск

- Нажмите `/` в списке проектов для входа в режим поиска
- Вводите текст для фильтрации по имени
- `Enter` — открыть первый результат, `Esc` — отмена

### Инспектор сети

- `Enter` на запросе — открыть детальный вид
- `Space` — отметить/снять отметку
- `c` — очистить все отметки
- `g` — сгенерировать API-файл из отмеченных запросов
- `/` — фильтрация по URL/методу
- `↑` / `↓` / `PageUp` / `PageDown` / `Home` / `End` — навигация

## Конфигурация

### Глобальный конфиг

Путь: `~/.config/ewd-tui/config.toml`

```toml
keymap = "emacs"
```

Допустимые значения: `emacs`, `vim`, `vscode`. По умолчанию: `emacs`.

### Конфиг проекта

Путь: `~/.config/ewd-tui/projects/<dir>/config.toml`

```toml
name = "Мой проект"
url = "http://localhost:3000"
entry = "src/main.js"
watch_extensions = ["js", "ts", "jsx", "tsx", "json", "json5"]
```

- **name** — отображаемое имя
- **url** — URL, загружаемый во вкладке браузера
- **entry** — входной файл для esbuild
- **watch_extensions** — расширения файлов, запускающих пересборку (по умолчанию: js, ts, jsx, tsx, json, json5)

## Структура директорий

```
~/.config/ewd-tui/
├── config.toml          # Глобальный конфиг
├── projects/            # Конфиги проектов
│   └── <dir>/
│       └── config.toml  # Конфиг проекта
│       └── <entry>      # Входной файл (генерируется при создании)
└── bundles/             # Вывод esbuild
    └── <dir>.js         # Собранный бандл
```

## Решение проблем

### ewd-daemon не найден

Соберите `ewd-daemon` и добавьте в PATH, или установите `EWD_DAEMON_PATH`:

```bash
cargo build --release -p ewd-daemon
export EWD_DAEMON_PATH=./target/release/ewd-daemon
ewd-tui
```

### esbuild не найден

Установите esbuild через менеджер пакетов (см. Системные требования выше).

### Проблемы с отображением в терминале

- Убедитесь, что терминал поддерживает 256 цветов или true color
- Установите `TERM=xterm-256color`, если цвета отображаются некорректно
- Некоторым терминалам может потребоваться `COLORTERM=truecolor`

### Сокет уже существует

Если демон ранее аварийно завершился, файл сокета может остаться:

```bash
rm ~/.config/ewd-tui/ewd-tui-<pid>.sock
```

### Отладочное логирование

```bash
RUST_LOG=debug ewd-tui 2>ewd-tui.log
```
