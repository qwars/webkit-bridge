# EWD — Emacs-клиент для WebKit Daemon

Emacs-клиент для демона [webkit-bridge](../../README-ru.md), обеспечивающий автоматизацию браузера, управление вкладками и веб-сёрфинг прямо из Emacs через WebKitGTK.

**Версия пакета:** 0.9.0  
**Требования:** Emacs 28.1+ (рекомендуется 30+), с поддержкой `json-parse-string`

## Обзор

EWD (Emacs WebKit Daemon) — это Emacs Lisp пакет, который подключается к `ewd-daemon` через Unix-сокет, используя протокол JSON-RPC 2.0. Он предоставляет **дашборд** для визуального управления вкладками, **программный API** для скриптинга и автоматизации, **JS-мост** для пользовательских обработчиков JavaScript-сообщений и **отладочный лог** с секциями на основе Org-mode.

**EWD — это не браузер.** Это клиент, который взаимодействует с автономным демоном `ewd-daemon`, управляющим реальными экземплярами WebKitGTK.

### Состав пакета

Пакет состоит из трёх файлов:

| Файл               | Описание                                                                                   |
|--------------------|--------------------------------------------------------------------------------------------|
| `ewd.el`           | Ядро — подключение, протокол JSON-RPC, синхронный/асинхронный API, система JS-обработчиков |
| `ewd-dashboard.el` | Дашборд — табличное отображение вкладок в буфере `*ewd*` с интерактивными командами        |
| `ewd-debug.el`     | Отладка — лог на основе Org-mode в буфере `*ewd-debug*` с по вкладкам                      |

## Возможности

### Управление вкладками
- Создание, закрытие, навигация и перезагрузка вкладок
- **Показ/скрытие вкладок**: переключение видимости GTK-окна для любой вкладки (полезно для CAPTCHA и интерактивных страниц)
- Буфер дашборда `*ewd*` с табличным отображением
- Push-обновления: дашборд автоматически обновляется через уведомления `tabs_changed`
- Визуальное выделение: видимые вкладки подсвечиваются; ID, URL, заголовок и статус видимости отображаются в колонках

### Выполнение JavaScript
- Выполнение произвольного JavaScript в контексте любой вкладки
- Получение результатов обратно в Emacs для дальнейшей обработки
- Идеально для веб-скрапинга и автоматизации

### JS-мост (пользовательские обработчики)
- Регистрация обработчиков JavaScript через `ewd-register-js-handler`
- Получение сообщений от JavaScript-кода, выполняющегося в браузере
- Полезно для создания интерактивных интеграций Emacs-браузер

### Безопасность и изоляция
- Контроль доступа на основе владельца: Emacs может управлять только созданными им вкладками
- Вкладки, созданные другими клиентами (например, `wkctl` или другими экземплярами Emacs), видны, но недоступны для изменений
- Автоматическая очистка: все вкладки, принадлежащие Emacs, закрываются при выходе из Emacs (без запросов подтверждения)

### Дашборд
- Табличный формат: колонки URL, видимость, заголовок и ID
- Полностью клавиатурное управление: закрытие, показ, скрытие, eval, просмотр вкладок без выхода из Emacs
- Автообновление через push-уведомления от демона
- Состояния «нет подключения» и «нет вкладок» с подсказками

### Отладочное логирование
- Буфер `*ewd-debug*` на основе Org-mode с секциями для каждой вкладки
- Пакетная отложенная вставка (сброс при бездействии Emacs)
- Сохранение состояния свёрнутости, позиции курсора и прокрутки между сбросами
- Динамическое обновление заголовков секций (изменения URL и заголовка отражаются автоматически)

## Требования

### Emacs
- Emacs 28.1+ (рекомендуется 30+)
- Скомпилирован с поддержкой `json-parse-string`

### Демон
- `ewd-daemon` должен быть собран и доступен в `PATH`
- Сокет доступен по адресу `$XDG_RUNTIME_DIR/webkit-bridge.sock` (по умолчанию)
- Переопределение через переменную окружения `EWD_SOCKET_PATH` или настройку `ewd-socket-path`
- Демон может быть автоматически запущен EWD, если `ewd-daemon` найден в `PATH`
- См. [README webkit-bridge](../../README-ru.md) для установки демона

### Система
- Unix-подобная ОС с поддержкой Unix domain sockets
- Linux, BSD, macOS (с соответствующими путями к сокетам)

## Установка

### Ручная установка

Скопируйте директорию `ewd/` в ваш Emacs load path:

```bash
mkdir -p ~/.emacs.d/lisp
cp -r ewd/ ~/.emacs.d/lisp/
```

Добавьте в ваш `init.el`:

```elisp
(add-to-list 'load-path "~/.emacs.d/lisp/ewd")
(require 'ewd)
```

### Использование use-package

```elisp
(use-package ewd
  :load-path "~/.emacs.d/lisp/ewd"
  :config
  (setq ewd-socket-path "/run/user/1000/webkit-bridge.sock"))
```

## Конфигурация

### Переменные настройки

Доступ через `M-x customize-group RET ewd RET`:

| Переменная                  | По умолчанию            | Описание                                                                                                       |
|-----------------------------|-------------------------|----------------------------------------------------------------------------------------------------------------|
| `ewd-socket-path`           | `nil` (автоопределение) | Путь к сокету демона. Если `nil`, используется `$EWD_SOCKET_PATH`, затем `$XDG_RUNTIME_DIR/webkit-bridge.sock` |
| `ewd-dashboard-enabled`     | `t`                     | Включить дашборд                                                                                               |
| `ewd-dashboard-url-width`   | `45`                    | Ширина колонки URL в дашборде                                                                                  |
| `ewd-dashboard-title-width` | `35`                    | Ширина колонки TITLE в дашборде                                                                                |
| `ewd-dashboard-id-width`    | `8`                     | Ширина колонки ID (первые N символов UUID)                                                                     |

### Пример конфигурации

```elisp
(use-package ewd
  :load-path "~/.emacs.d/lisp/ewd"
  :custom
  (ewd-socket-path "/run/user/1000/webkit-bridge.sock")
  (ewd-dashboard-url-width 50)
  (ewd-dashboard-title-width 40))
```

## Использование

### Подключение к демону

```elisp
M-x ewd-connect
```

EWD сначала ищет запущенный процесс `ewd-daemon`. Если процесс не найден, но бинарник демона есть в `PATH`, EWD автоматически запустит его. Затем происходит подключение через Unix-сокет.

Отключение:

```elisp
M-x ewd-disconnect
```

### Глобальные горячие клавиши

Все команды привязаны к префиксу `C-c w`:

| Клавиши   | Команда                           | Описание                                             |
|-----------|-----------------------------------|------------------------------------------------------|
| `C-c w c` | `ewd-connect`                     | Подключиться к демону (автозапуск при необходимости) |
| `C-c w d` | `ewd-disconnect`                  | Отключиться от демона                                |
| `C-c w t` | `ewd-create-tab`                  | Создать новую вкладку (запрашивает URL)              |
| `C-c w l` | `ewd-list-tabs` / `ewd-dashboard` | Показать дашборд `*ewd*`                             |
| `C-c w k` | `ewd-close-tab`                   | Закрыть вкладку по ID                                |
| `C-c w e` | `ewd-eval`                        | Выполнить JavaScript во вкладке                      |
| `C-c w n` | `ewd-navigate`                    | Перейти по новому URL во вкладке                     |
| `C-c w r` | `ewd-reload`                      | Перезагрузить вкладку                                |
| `C-c w o` | `ewd-switch-to-tab`               | Открыть URL вкладки в системном браузере             |
| `C-c w S` | `ewd-show-tab`                    | Показать вкладку в GTK-окне                          |
| `C-c w H` | `ewd-hide-tab`                    | Скрыть вкладку (перевести в headless)                |

### Дашборд (буфер `*ewd*`)

Нажмите `C-c w l`, чтобы открыть дашборд. Он отображает все открытые вкладки в табличном формате:

```
URL                          | VIS   | TITLE                            | ID
-----------------------------------------------------------------------------------
https://example.com          | yes   | Example Domain                   | ac93f48c
https://google.com           | no    | Google                           | bb91aed9
```

**Горячие клавиши в дашборде:**

| Клавиша     | Команда                    | Описание                                  |
|-------------|----------------------------|-------------------------------------------|
| `g`         | `ewd-dashboard-refresh`    | Обновить список                           |
| `k`         | `ewd-dashboard-close`      | Закрыть вкладку под курсором              |
| `o` / `RET` | `ewd-dashboard-browse-url` | Открыть URL вкладки во внешнем браузере   |
| `s`         | `ewd-dashboard-show`       | Показать вкладку в GTK-окне               |
| `h`         | `ewd-dashboard-hide`       | Скрыть вкладку (перевести в headless)     |
| `e`         | `ewd-dashboard-eval`       | Выполнить JS во вкладке под курсором      |
| `t`         | `ewd-create-tab`           | Создать новую вкладку                     |
| `c`         | `ewd-dashboard-copy-id`    | Скопировать полный ID вкладки в kill-ring |
| `q`         | `quit-window`              | Закрыть дашборд                           |

### Отладочный лог (буфер `*ewd-debug*`)

Отладочный лог создаётся автоматически при начале логирования EWD. Он использует Org-mode для структурированного логирования по вкладкам:

```
* EWD Debug Log [[ipc][ipc]]
#+BEGIN_EXAMPLE
[14:30:01] Подключение к демону
[14:30:02] Запрос: create {"url":"https://example.com"}
#+END_EXAMPLE

* Example Domain [[https://example.com][link]] [[ac93f48c-...][uuid]]
#+BEGIN_EXAMPLE
[14:30:03] Вкладка создана: ac93f48c-9b3b-4b64-8852-966d2af207b9
[14:30:05] Навигация на https://example.com
#+END_EXAMPLE
```

Каждая вкладка получает свой раздел. Разделы можно сворачивать/разворачивать с помощью Org-mode. Буфер обновляется в реальном времени с сохранением позиции курсора и состояния свёрнутости.

### Типичный рабочий процесс

1. **Запустите демон** (если не запущен как сервис):
   ```bash
   ewd-daemon
   ```

2. **Подключитесь из Emacs:**
   `M-x ewd-connect` или нажмите `C-c w c`

3. **Создайте вкладку:**
   `M-x ewd-create-tab` или нажмите `C-c w t`, введите URL, нажмите `RET`

4. **Просмотрите и управляйте вкладками:**
   `M-x ewd-dashboard` или нажмите `C-c w l`
   - Перемещайтесь стрелками
   - Нажмите `k` для закрытия, `o` или `RET` для открытия в браузере
   - Нажмите `s` для показа в GTK-окне, `h` для скрытия

5. **Решите CAPTCHA или работайте с интерактивной страницей:**
   - Нажмите `s` на вкладке, чтобы показать её GTK-окно
   - Решите CAPTCHA вручную
   - Нажмите `h`, чтобы снова скрыть окно

6. **Выполните JavaScript:**
   `M-x ewd-eval` или нажмите `C-c w e`, введите ID вкладки, введите скрипт
   Результат появится в минибуфере

7. **Выйдите из Emacs:**
   - Все вкладки, принадлежащие этому экземпляру Emacs, автоматически закрываются
   - Без запросов подтверждения
   - Вкладки других клиентов остаются нетронутыми

## Программный API

### Синхронные функции

Отправляют запрос и ждут ответа:

```elisp
(ewd-create-tab url &optional visible)
(ewd-close-tab tab-id)
(ewd-navigate tab-id url)
(ewd-reload tab-id)
(ewd-show tab-id)
(ewd-hide tab-id)
(ewd-eval tab-id script)
(ewd-list-tabs)
(ewd-shutdown)
```

### Асинхронные функции

Принимают callback-функции для успеха и ошибки:

```elisp
(ewd-create-tab-async url success-cb error-cb &optional visible)
(ewd-close-tab-async tab-id success-cb error-cb)
(ewd-navigate-async tab-id url success-cb error-cb)
(ewd-reload-async tab-id success-cb error-cb)
(ewd-show-async tab-id success-cb error-cb)
(ewd-hide-async tab-id success-cb error-cb)
(ewd-eval-async tab-id script success-cb error-cb)
(ewd-list-tabs-async success-cb error-cb)
(ewd-shutdown-async success-cb error-cb)
```

### Система JS-обработчиков

Зарегистрируйте обработчик для получения сообщений от JavaScript в браузере:

```elisp
(ewd-register-js-handler "my-handler"
  (lambda (tab-id data)
    (message "EWD JS от %s: %s" tab-id data)))
```

JavaScript в браузере может отправлять сообщения через менеджер пользовательского контента WebKit.

## Примеры

### Веб-скрапинг

```elisp
;; Получить заголовок страницы
(ewd-eval "tab-id" "document.title")

;; Извлечь все ссылки
(ewd-eval "tab-id"
  "Array.from(document.querySelectorAll('a')).map(a => ({href: a.href, text: a.textContent}))")

;; Получить содержимое страницы как текст
(ewd-eval "tab-id" "document.body.innerText")
```

### Скрипт автоматизации

```elisp
(defun my-open-research-tabs ()
  "Открыть набор вкладок для исследования."
  (interactive)
  (dolist (url '("https://google.com"
                 "https://arxiv.org"
                 "https://scholar.google.com"))
    (ewd-create-tab url)))
```

### Интеграция с org-mode

```elisp
(defun my-org-browse-url-in-ewd (url)
  "Открыть URL в EWD вместо браузера по умолчанию."
  (interactive "sURL: ")
  (ewd-create-tab url))

;; Использовать как обработчик ссылок org-mode
(setq browse-url-browser-function #'my-org-browse-url-in-ewd)
```

### Асинхронное создание вкладки с уведомлением

```elisp
(ewd-create-tab-async
 "https://example.com"
 (lambda (msg)
   (let ((tab-id (ewd--extract-create-id msg)))
     (message "Вкладка создана: %s" tab-id)))
 (lambda (err)
   (message "Ошибка создания вкладки: %s" err)))
```

## Решение проблем

### "EWD: Not connected. Run M-x ewd-connect first"

Демон не запущен или вы не подключены. Выполните `M-x ewd-connect`. EWD попытается автоматически запустить демон, если бинарник найден в `PATH`.

### "Socket file does not exist"

Проверьте путь к сокету:

```bash
ls -l $XDG_RUNTIME_DIR/webkit-bridge.sock
```

Если демон использует кастомный путь, установите `ewd-socket-path`:

```elisp
(setq ewd-socket-path "/custom/path/webkit-bridge.sock")
```

### Дашборд не обновляется автоматически

Дашборд обновляется автоматически при получении `tabs_changed` уведомлений от демона. Если этого не происходит:

- Нажмите `g` в буфере `*ewd*` для ручного обновления
- Убедитесь, что демон запущен и подключён
- Проверьте логи демона на наличие ошибок
- Убедитесь, что `ewd-dashboard-enabled` установлен в `t`

### "EWD: Error parsing message"

Возможно, вы используете несовместимую версию демона. Убедитесь, что используете последнюю версию `ewd-daemon`, поддерживающую протокол `tabs_changed`.

### Отладочное логирование

Буфер отладки (`*ewd-debug*`) создаётся автоматически. Для просмотра:

```elisp
(switch-to-buffer "*ewd-debug*")
```

Используйте клавиши Org-mode для сворачивания/разворачивания секций (`TAB` на заголовке, `S-TAB` для глобального цикла).

## Архитектура

```
┌─────────────┐         Unix-сокет             ┌──────────────────┐
│   Emacs     │  ◄──── JSON-RPC 2.0 ────►      │  ewd-daemon      │
│  (ewd.el)   │        (формат NDJSON)         │                  │
└──────┬──────┘                                └──────────────────┘
       │                                              │
  ┌────┴────┐                                ┌────────┴────────┐
  │ *ewd*   │                                │   WebKitGTK     │
  │дашборд  │                                │   (вкладки)     │
  └─────────┘                                └─────────────────┘
       │
  ┌────┴────┐
  │ *ewd-   │
  │ debug*  │
  └─────────┘
       │
  ┌────┴────┐
  │ JS      │
  │обраб-ки │
  └─────────┘
```

- **`ewd.el`** — Ядро: отправляет JSON-RPC запросы, получает ответы и `tabs_changed` уведомления. Предоставляет синхронный и асинхронный API, регистрацию JS-обработчиков и управление жизненным циклом демона.
- **`ewd-dashboard.el`** — Дашборд: отображает буфер `*ewd*` с табличным представлением всех вкладок. Предоставляет управление вкладками с клавиатуры.
- **`ewd-debug.el`** — Отладка: логирует весь IPC-трафик и события вкладок в буфер `*ewd-debug*`, используя секции Org-mode, с пакетной отложенной вставкой.
- **Демон (`ewd-daemon`)** — Управляет экземплярами WebKitGTK, обеспечивает правила владения, рассылает уведомления об изменениях через `tabs_changed`.
